§1.1为什么是 LTspice

LTspice 是 Analog Devices 维护的免费 SPICE 仿真器：启动快、收敛性好、自带大量真实器件模型，工业界与高校都在用。对自学者更关键的一点是——它既能画原理图（.asc），也能直接读纯文本网表（.cir / .net）。

本书统一使用网表：.cir 是纯文本，可以放进 Git、可以 diff、可以由 HTML 代码块自动生成，也更容易把“电路”当代码来读。想看原理图时，LTspice 也能把网表里的元件逐一键入画布。

§1.2四类分析，回答四个问题

指令回答的问题典型用法
.op静态工作点：各节点电压、各管 Id / gm / 工作区确认偏置是否成立（结果在 Error Log，不弹波形）
.dc某个直流源扫描时，电路怎么变化二极管 I-V 曲线、MOS 输出特性、传输曲线
.tran随时间怎么变化充放电、放大波形、失真、启动过程、振荡
.ac不同频率下增益与相位波特图、带宽、相位裕度、滤波器

另有 .noise（噪声）、.tf（直流小信号传递函数与输入/输出电阻）、.four（频谱 / THD），见第 2 章与第 21 章。

§1.3第一个波形：逐步操作

  1. 复制下方代码块，保存为 sim/01-rc-charge.cir（或直接打开仓库里的同名文件）。
  2. File → Open 打开它，点工具栏 Run（奔跑小人）。第一次会弹出波形窗口，标题是 Transient Analysis。
  3. 右键波形区 → Add Trace → 选 V(out)；也可以先用 V(in) 看激励。
  4. 把鼠标移到曲线上，游标会显示坐标；按住左键拖一段可测 Δt、ΔV、斜率。
  5. 菜单 View → SPICE Error Log（或 Ctrl+L）里能找到 .meas 的测量结果与警告。
常见坑

纯网表没有原理图可点，必须手动 Add Trace；只有 .op 时不会弹出波形窗口，别以为仿真没跑。网表注释请用英文 ASCII，中文注释在部分版本会乱码。

§1.4报错时先看这三处

  • Floating node / No DC path to ground：某节点只有电容或理想电流源相连，SPICE 求不出直流解。给它并联一个大电阻（如 1G）或在电容上加初始条件。
  • Unknown model / Can't find library：用了 .model 未定义的器件名，或 .lib 路径不对。本书全部自包含定义模型，不依赖外部库。
  • Timestep too small / Convergence failed：瞬态不收敛。检查是否有理想开关、无串联电阻的电容环路、过陡的 PULSE 边沿；给边沿一个有限上升时间（如 1n），必要时加 .options gmin=1n。

§仿真实验

实验 1-1：RC 充电与时间常数

* Ch01 RC charging transient - first LTspice run
V1 in 0 PULSE(0 5 0 1u 1u 5m 10m)
R1 in out 10k
C1 out 0 100n
.tran 0 8m 0 10u
* tau = R1*C1 = 1ms ; V(out) = 5*(1-exp(-t/tau))
.meas TRAN v_1m FIND V(out) AT 1m
.meas TRAN v_5m FIND V(out) AT 5m
.end

操作：Run 后 Add Trace 选 V(out) 与 V(in)；在 Error Log 里读两条 .meas 结果。　预期与判读：τ = 10k × 100n = 1 ms；t = 1 ms 时 V(out) ≈ 5(1−e⁻¹) = 3.16 V；t = 5τ = 5 ms 时约 4.97 V。把 R1 改成 20k，τ 翻倍，曲线变缓。　文件位置：part0/01-ltspice-quickstart/sim/01-rc-charge.cir

代码块右上角可一键复制；本仓库 sim/*.cir 由 tools/extract_netlists.py 从这些代码块自动抽取，因此页面与可运行网表永远一致。网表注释统一使用 ASCII 英文。

§常见误区

  • 以为 .op 会弹波形：它只写 Error Log。
  • PULSE 上升时间写 0 导致仿真警告或步长过小，给 1u 这类有限值即可。
  • 直接把波形截图当结论，没有记下手算预期值。

§习题与思考

  1. 把 C1 改成 220n，先手算 t = 1 ms 时的 V(out)，再仿真核对。
  2. 添加 .meas 测出 V(out) 到达 2.5 V 的时刻，与 0.693τ 比较。
